# Spec: douyin-transcriber — 抖音视频语音转录 CLI 工具

**日期**: 2026-09-20
**状态**: 草案

---

## 1. 问题陈述

用户在浏览抖音时经常遇到需要提取视频语音内容的场景（如记录要点、整理口述内容、做笔记）。现有方案全部聚焦于"下载视频"，而用户**完全不需要视频画面**，只需要语音对应的**文字内容**。

当前没有一款轻量工具能做到：粘贴一个抖音分享链接 → 直接得到文字转录结果。用户被迫经历"下载视频 → 手动提取音频 → 找 ASR 工具转录"的多步手工流程。

## 2. 方案概述

一个 Python CLI 工具，接收抖音分享链接作为输入，内部完成：

```
抖音分享链接
    ↓ yt-dlp 提取音频流（不下载视频）
临时音频文件
    ↓ MiniMax ASR API 转录
结构化文本结果
    ↓ 写入文件
最终输出（.txt）
    ↓ 清理
临时音频删除
```

用户只需执行一条命令，得到一个文本文件。

## 3. 接缝（Seams）

工具内部划分为四个可独立测试的稳定接口：

| 接缝 | 职责 | 输入 | 输出 |
|------|------|------|------|
| `AudioExtractor` | 从抖音链接提取音频 | URL (str) | 本地临时音频文件路径 (Path) |
| `Transcriber` | 调用 ASR 将音频转文字 | 音频文件路径 (Path) | `TranscriptionResult`（含段落列表，每段有 text + 可选 start/end 时间） |
| `OutputFormatter` | 将转录结果格式化为文本 | `TranscriptionResult` + 模式标志 | 格式化后的字符串 |
| `CLI` | 解析参数、串联管线、管理文件输出与清理 | sys.argv | 退出码 + 文件写入副作用 |

## 4. 用户故事

### US-1: 基本转录
**作为**用户，**我想**执行 `douyin-transcriber <抖音分享链接>`，**以便**得到一个包含该视频语音文字内容的文本文件。

验收标准：
- 命令接受一个抖音分享链接（`https://v.douyin.com/xxx/` 格式）作为位置参数
- 执行完成后在当前目录生成一个 `.txt` 文件
- 文件内容为该视频语音的纯文字转录
- 执行过程中的临时音频文件被自动删除

### US-2: 时间戳模式
**作为**用户，**我想**加 `--timestamps` 参数运行命令，**以便**得到每句话带时间标记的转录文本。

验收标准：
- 加 `--timestamps` 后，输出文件中每段文字前附带时间戳
- 时间戳格式为 `[MM:SS]`
- 不加该参数时，输出为纯文本（无时间戳）

### US-3: 输出文件命名
**作为**用户，**我想**输出的文本文件有可辨识的名字，**以便**知道它对应哪个视频。

验收标准：
- 默认文件名基于视频标题或 ID，如 `douyin_<video_id>.txt`
- 可通过 `-o <path>` 参数指定输出文件路径
- 若指定路径已存在，报错并退出（不覆盖）

### US-4: API Key 缺失提示
**作为**用户，**当**我没有设置 `MINIMAX_API_KEY` 环境变量时运行命令，**我想**看到清晰的错误提示，**以便**知道该怎么修复。

验收标准：
- 未设置环境变量时，工具输出明确的错误信息（如"请设置环境变量 MINIMAX_API_KEY"）并以非零退出码退出
- 不抛出原始异常堆栈

### US-5: 链接无效处理
**作为**用户，**当**我传入了一个无效的或非抖音的链接时，**我想**看到清晰的错误提示，**以便**知道问题出在哪。

验收标准：
- 非抖音域名链接 → 报错"仅支持抖音链接"
- 抖音链接但视频不存在/已删除 → 报错"视频不可用"
- 所有错误以非零退出码退出

### US-6: 进度反馈
**作为**用户，**当**工具在运行时，**我想**看到当前进行到哪一步，**以便**知道它没有卡死。

验收标准：
- 在终端打印简要进度信息（如"正在提取音频…"、"正在转录…"、"已保存到 xxx.txt"）
- 进度信息输出到 stderr，不污染 stdout

## 5. 已定决策

| 决策 | 理由 |
|------|------|
| 仅支持抖音，不做多平台 | 聚焦单一场景，降低维护复杂度 |
| ASR 用 MiniMax API，不用本地 Whisper | 用户指定；无需本地 GPU 资源 |
| API Key 通过环境变量传入 | 安全，不写入代码或配置文件 |
| 音频用 yt-dlp 提取 | 成熟方案，可直接提取音频流而不下载视频 |
| 输出始终保存文件，不打印到终端 | 用户需求明确 |
| 默认纯文本，`--timestamps` 切换时间戳模式 | 纯文本更通用，时间戳按需开启 |
| Python 开发 | ASR/音视频生态最丰富 |

## 6. 测试决策

| 接缝 | 测试策略 | "完成"标准 |
|------|----------|------------|
| `AudioExtractor` | Mock yt-dlp 调用，验证参数正确、返回值正确 | 给定 URL → 返回合法临时文件路径 |
| `Transcriber` | Mock MiniMax API 响应，验证请求格式和结果解析 | 给定音频路径 → 返回含段落和时间的结构 |
| `OutputFormatter` | 纯函数测试，输入 `TranscriptionResult` → 验证输出字符串格式 | 纯文本模式无时间戳；时间戳模式每段有 `[MM:SS]` 前缀 |
| `CLI` | 集成测试：mock 外部依赖，验证完整管线流程 | 端到端运行后文件存在、内容正确、临时文件已清理 |
| 错误路径 | 验证缺失 API Key、无效链接、文件已存在等场景的退出码和错误信息 | 每种错误有明确提示 + 非零退出码 |

使用 **pytest** 作为测试框架。

## 7. 明确不做

- ❌ 不下载视频文件（只提取音频流）
- ❌ 不支持抖音以外的平台（快手、B站、小红书等）
- ❌ 不做本地 ASR（不依赖 Whisper 本地模型）
- ❌ 不做 GUI / Web 界面
- ❌ 不做批量处理（一次一个链接）
- ❌ 不做字幕格式输出（SRT/ASS）
- ❌ 不保留临时音频文件
- ❌ 不覆盖已存在的输出文件

## 8. 补充说明

### 外部依赖清单
- **yt-dlp**: Python 包，`pip install yt-dlp`
- **ffmpeg**: 系统级依赖，yt-dlp 音频转码所需。工具启动时应检查 ffmpeg 是否可用，不可用时给出安装提示
- **MiniMax ASR API**: 需用户自行申请 API Key
